## 2026-11-03 사건 갈라짐 수정 (B안, VM 미검증)
- 결정과 이유: 사용자가 B안(두 원인 모두 수정)을 골랐다. 잘못 합쳐져도 긴급 알림 자체는 빠지지 않고, 잃는 것은 정지 물체를 따로 관리하던 기록 정도라서다.
- 한 일:
  - 놓친 걷는 대상을 이어 붙일 때 확인 여부를 보지 않는다.
  - 새로 잡힌 물체가 생긴 지 10초 안에 움직이고, 3 m 안에 지금 안 보이며 새 물체가 나타난 뒤로 한 번도 안 보인 정지 사건이 있으면, 그 정지 물체가 걷기 시작한 것으로 보고 합친다.
  - 합친 사건은 알림에 `(같은 대상: 사건 #N)`을 붙여, 먼저 다른 번호로 알린 경우에도 헷갈리지 않게 했다.
- 바뀐 파일: `security_patrol/incident_logic.py`, `alert_format.py`, `test/test_incident_logic.py`, `test/test_telegram_alert.py`
- 확인 결과: VM 로그 순서를 그대로 재현한 시험이 수정 전에는 실패하고 수정 뒤 사건 1개로 통과했다. 멀리서 움직이는 대상, 정지 물체가 지금도 보이는 경우, 오래된 새 사건은 합치지 않는 것도 시험했다. 맥 단위 시험 50개 통과.
- 미확인: VM 재시험. 물체가 두 군데에서 동시에 보인 현상(아래)은 이 수정과 무관하며 원인을 모른다.

## 2026-11-03 토큰 노출 사고와 수정
- 문제와 해결:
  - 첫 `telegram_setup` 실행 때 붙여넣은 값에 제어 문자(`\x1b`)와 토큰 중복이 섞였다. 그러자 `http.client.InvalidURL`이 URL 전체(토큰 포함)를 오류 메시지에 넣었고 traceback으로 VM 화면에 찍혔다. 이 오류는 `ValueError`가 아니라 `HTTPException` 계열이라 기존 예외 처리에 걸리지 않았다. 토큰을 오류에 넣지 않는다는 설계를 내가 잘못 검증한 것이다.
  - 수정: 모든 예외를 잡아 종류 이름만 남기고, 형식이 맞지 않는 토큰으로는 요청을 보내지 않는다. `telegram_setup`은 입력에서 토큰 부분만 꺼내고 입력 내용은 출력하지 않는다. 같은 상황을 재현하는 시험을 추가했다(맥 단위 시험 42개 통과).
  - 화면과 Claude 대화 기록에 토큰이 남았으므로 `@BotFather`의 `/revoke`로 재발급을 권했다. 사용자가 새 토큰을 받아 `telegram_setup`을 다시 실행했고, 오류 없이 `완료`까지 나왔다(화면에 토큰 없음).
- 바뀐 파일: `security_patrol/telegram_link.py`, `telegram_setup.py`, `test/test_telegram_alert.py`

## 2026-11-02 텔레그램 알림 구현 (VM 미검증)
- 한 일: `/anomaly/alerts`를 텔레그램으로 보내고 확인 버튼을 `/anomaly/ack`로 전달하는 `alert_notifier`와, 처음 한 번 쓰는 `telegram_setup`을 만들었다.
- 결정과 이유:
  - 사용자가 텔레그램 봇을 골랐다. VM이 먼저 텔레그램 서버에 연결하는 방식이라 VM 네트워크를 바꾸지 않아도 버튼 입력을 받을 수 있다. ntfy는 버튼이 VM으로 직접 들어와야 하고, 웹페이지는 잠긴 휴대폰에 푸시를 띄우기 어렵다.
  - 추가 패키지 없이 표준 라이브러리로 호출한다.
  - 토큰은 저장소 밖 파일에 권한 600으로 저장한다. 토큰이 URL에 들어가므로 오류 메시지에 URL을 넣지 않는다.
  - 전송과 수신은 별도 스레드에서 한다. 인터넷이 끊겨도 감지와 순찰을 막지 않고, 다시 연결되면 순서대로 보낸다.
  - 등록한 대화방의 버튼만 받는다. 사건 번호는 재실행하면 1부터 다시 시작하므로, 이전 실행의 버튼은 실행 번호를 비교해 무시한다.
  - 문구는 측정한 사실만 쓰고 침입자나 사람이라고 단정하지 않는다. 위치에는 좌표와 가장 가까운 순찰 지점 이름을 함께 넣는다.
- 바뀐 파일: `security_patrol/alert_format.py`, `telegram_link.py`, `alert_notifier.py`, `telegram_setup.py`, `launch/detect.launch.py`, `setup.py`, `test/test_telegram_alert.py`, `README.md`
- 확인 결과: 맥 단위 시험 40개 통과(새 시험 16개는 맥의 가짜 HTTP 서버 사용). 재시도, 순서 유지, 토큰 비노출, 다른 대화방 차단, 이전 실행 버튼 차단을 확인했다.
- 미확인: 실제 텔레그램 서버 연결, `telegram_setup` 전체 흐름, 휴대폰 버튼부터 재알림이 멈추기까지. ROS 노드 실행도 VM에서 아직 안 했다.
- 알려진 한계: 대기열은 200개까지이고 넘치면 오래된 알림부터 버린다. `incident_manager`를 다시 켜면 사건 기록이 사라진다.
- 다음 할 일: 사용자가 `@BotFather`로 봇을 만든 뒤 VM에서 `telegram_setup` 실행, 그다음 침입자로 실제 알림과 확인 버튼 시험.
