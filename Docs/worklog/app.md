## 2026-11-10 가상머신 첫 실행: 화면 404 수정
- 확인 결과: VM 에서 `app_server` 실행, 지도 160x120 수신. 맥에서 WebSocket 접속 시 지도·로봇 위치(-3.0, 0.0)·라이다 360점·순찰 꺼짐 정상. 그런데 화면 파일(`/`, `/app.js`)이 404.
- 문제와 해결: `colcon build --symlink-install` 은 화면 파일을 src 원본에 대한 링크로 설치한다. 웹 서버의 경로 검사가 링크를 따라간 실제 위치(src)로 판단해 "폴더 밖"으로 막았다. 링크를 따라가지 않는 경로 정리(normpath)로 '..' 만 막도록 바꿨다. 링크 파일 시험 추가(133개 통과).
- 바뀐 파일: `web_server.py`, `test/test_web_server.py`
- 수정 후 확인(`ce8b5e6`): VM 에서 화면 200, 맥 브라우저에 시뮬레이션 레이더 화면 정상. 사용자가 조이스틱(느리게 0.075 m/s)으로 시뮬레이션 로봇을 움직이는 것 확인(-3.0 → -1.6 m). 배터리·Wi-Fi 는 시뮬레이션에 값이 없어 `-`.
- 순찰 잠금 확인: VM 에서 patrol_node 실행 → 앱에 "순찰 이동 중 · 1바퀴 · 1번째 지점 출발점", 수동 주행 탭 "순찰 중에는 수동 주행을 할 수 없습니다", 조이스틱 흐리게 잠김.

## 2026-11-10 2단계: 조이스틱 수동 주행
- 한 일: 앱 수동 주행 탭에 조이스틱·속도 단계(느리게/보통)·정지 버튼, 컴퓨터용 방향키·WASD·스페이스. 서버는 앱 값으로 `cmd_vel` 발행.
- 결정과 이유 (안전 규칙, `app_logic.ManualDrive`·`guard_speed`):
  - 앱은 -1~1 비율만 보내고 최대 속도는 서버 파라미터로 정함. 앱 값을 믿지 않고 자름.
  - 누르는 동안 0.1초마다 보내고, 서버는 0.5초 못 받으면 스스로 정지. 손 뗌·탭 이동·창 벗어남·연결 끊김도 정지.
  - 정지 때 0 속도를 3번만 보내고 조용해짐. 계속 0 을 보내면 Nav2·키보드 조종과 다투기 때문.
  - 한 번에 한 화면만 조종(먼저 움직인 화면), 정지는 아무 화면이나.
  - 앞뒤 15 cm 안 라이다 점이 차체 폭 안에 있으면 그 방향 전후진만 막음(회전은 허용해 빠져나갈 수 있게). 차체 안쪽 점은 자기 몸으로 보고 무시.
  - 순찰 중인지는 `patrol/status` 발행자 수로 판단. 순찰 노드는 일이 생길 때만 상태를 내고 Ctrl+C 때 '정지'를 안 내서 마지막 메시지로는 알 수 없음.
  - 정지 판단 타이머는 실제 시간(steady clock). 시뮬레이션 시계가 멈춰도 끊김을 잡도록.
  - 실제 로봇은 회전이 명령의 약 25% 라 `max_angular:=1.8` 로 실행 ([real-robot](real-robot.md) Nav2 설정과 같은 이유).
- 바뀐 파일: `app_logic.py`(ManualDrive, guard_speed), `app_server.py`, `web/index.html·app.js·style.css`, `tools/app_preview.py`(조이스틱으로 가짜 로봇 운전, `--patrol`), `test/test_app_logic.py`, `README.md`.
- 확인 결과:
  - 단위 시험 132개 통과(3개 건너뜀), pyflakes·JS 문법 깨끗.
  - 가짜 ROS 로 app_server 시나리오 11개: 속도 자르기, 다른 화면 거절, 0.26 m 앞 벽에서 전진 0·회전 유지, 0.5초 끊김 정지(0 세 번 후 조용), 정지 버튼, 연결 끊김 정지, 순찰 시작 시 정지·순찰 중 거절, 종료 때 0 발행 모두 예상대로.
  - 미리보기에서 키보드 전진 → 손 떼면 정지, 창을 벗어나면 정지 확인. 웹소켓으로 상자 쪽 전진 → 상자 12 cm 앞에서 멈춤, 후진·회전 가능.
  - 확인 못 한 것: 가상머신 시뮬레이션·실제 로봇. 앱 서버가 강제 종료되면 마지막 속도가 남을 수 있는데, 펌웨어에 명령 끊김 정지가 있는지는 모름.

## 2026-11-09 1단계: 서버 노드 + 화면 뼈대 + 레이더 화면
- 한 일: 브라우저로 보는 관제 웹 앱 1단계. 레이더(로봇 중심)·지도 화면, 연결·배터리·Wi-Fi·위치 상태, 감지 물체 표시.
- 결정과 이유:
  - 사용자 선택: ① 웹 앱(설치 없음) ② 전용 앱 서버 노드 ③ 휴대폰 + 맥(맥 중계) ④ 기능 4개만(코스 선택, 수동 주행, 자동 주행, 레이더).
  - 단계: 1 서버+화면+레이더 → 2 조이스틱 수동 주행(손 떼거나 연결 끊기면 정지) → 3 코스 선택·자동 순찰 → 4 휴대폰 접속(맥 중계)+실제 로봇 → 5 마무리·README·커밋.
  - 웹 서버는 표준 라이브러리 asyncio 로 직접 구현(정적 파일 + WebSocket). 가상머신에 패키지를 더 설치하지 않으려고.
  - 라이다 점은 로봇 좌표(앞 x, 왼쪽 y)로 보내 화면에서 회전만 하면 되게 함. 지도는 base64, 모르는 칸(-1)은 255.
  - 상태는 5 Hz. 느린 휴대폰은 큐 8개를 넘으면 오래된 것부터 버림.
- 바뀐 파일: `security_patrol/web_server.py`, `app_logic.py`, `app_server.py`, `web/index.html·app.js·style.css`, `tools/app_preview.py`, `test/test_web_server.py`, `test/test_app_logic.py`, `setup.py`(web 파일·app_server 등록), `README.md`.
- 문제와 해결:
  - 캔버스가 아주 작을 때 원 반지름이 음수가 되어 그리기 루프가 멈춤 → 그리기를 try/catch 로 감싸고 80px 이하면 건너뜀.
  - 시험 종료 때 "Event loop is closed" 경고 → stop() 에서 연결·작업을 먼저 정리한 뒤 루프를 멈추도록 바꿈. 첫 시도는 self.loop 가 None 이 되어 30초 지연 → 루프를 지역 변수로 씀.
- 확인 결과:
  - 맥에서 `tools/app_preview.py`(가짜 방·로봇·사람)로 데스크톱·휴대폰 크기 화면 확인: 레이더에 벽·라이다·사람 후보, 지도 화면 이동·확대 정상.
  - 단위 시험 122개 통과(3개 건너뜀), pyflakes 깨끗.
  - 가짜 ROS 로 app_server 실행: 접속 시 지도 전송, TF 없으면 라이다 0점·위치 없음, TF 넣으면 라이다 360점·로봇 위치·배터리·Wi-Fi·순찰·물체 정상, 종료 정상.
  - 확인 못 한 것: 가상머신 시뮬레이션(Gazebo)에서 실제 실행.
