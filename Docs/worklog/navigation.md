# 자율주행 (3단계)

관련 문서: [mapping](mapping.md), [patrol](patrol.md), [real-robot](real-robot.md)

## 2026-10-27 3단계 완료: OmniMotionModel
- 한 일: 시뮬레이션 AMCL을 `OmniMotionModel`로 바꾸고, `nav_test`가 `/odom` 실제 위치도 검사하게 했다(`fffb870`).
- 결정과 이유: 이동 모델은 odom의 오차 특성에 맞춘다. 시뮬레이션 설정에만 Omni를 쓰고, 실제 로봇은 8단계에 별도 설정 파일로 Differential을 쓰기로 했다.
- 확인 결과: 4/4 PASS. 실제 위치 오차 0.16, 0.07, 0.19, 0.09 m. `loc_monitor` 최대 오차 0.16 m / 10°, 위치 잃음 0회.

## 2026-10-27 세 번째 시도: 가짜 PASS 발견
- 한 일: Differential을 유지하고 `alpha 0.1`, `z_hit 0.9`, `z_rand 0.1`로 조정했다(`f47fa0e`).
- 문제와 해결: 4/4 PASS였지만 실제 로봇은 마지막 목표에서 약 0.5 m 벗어나 있었다. Nav2의 "도착"은 AMCL이 믿는 위치 기준이기 때문이다. 회전할 때 σ도 1.3~2.5 m까지 올랐다. 그래서 위 Omni 모델과 실제 위치 검사로 넘어갔다.

## 2026-10-27 두 번째 시도: CPU는 원인이 아니었음
- 한 일: Gazebo 화면을 끄고(`gui:=false` 기본) Nav2 주기를 낮췄으며, 점검 노드 `loc_monitor`를 추가했다(`aa617fa`).
- 문제와 해결:
  - RTF가 1.00인데도 제자리 회전을 시작하자 AMCL σ 방향이 14°에서 121°까지 올라 위치를 잃었다. CPU 부족 가설은 틀렸다.
  - 원인 판단: 4륜 로봇이 회전할 때의 흔들림을 Differential 모델이 이동 방향으로 과하게 해석한다. 흔들림 크기(1~2 cm)는 직접 재지 않은 추정이다.
  - `loc_monitor`가 위치를 잃는 순간 꺼졌다. rclpy는 같은 호출 위치에서 로그 심각도가 바뀌면 `ValueError`를 낸다. 호출을 나눠 고쳤다.

## 2026-10-27 첫 시험: 위치 착각 5.6 m
- 한 일: `nav2_params.yaml`, `nav.launch.py`, `nav_test.py`를 만들었다(`42f9102`). 컨트롤러는 Regulated Pure Pursuit.
- 문제와 해결: 3/4 통과, 마지막 목표는 시간 초과. 실제 (3.24, -0.17, -25°)인데 AMCL은 (-2.40, -0.07, 165°)로 추정했다. 구역이 180° 돌리면 비슷한 모양이라 반대편으로 착각한 것으로 본다.
- 시도했다가 버린 것: 로봇 기울기 가설(숫자로 기각), CPU 부족 가설(위 항목).
